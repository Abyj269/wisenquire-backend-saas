# Runbook: email sender domain (SPF, DKIM, DMARC)

Module 02 P2 item 4 (Step 6.2). The sending domain is **not decided yet**. Everything below uses the placeholder
`mail.example.com`; replace it with the real domain before going live. Mail is sent over SMTP
(`SMTP_HOST`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `MAIL_FROM_ADDRESS`); there is no provider API.

## 1. Choose the sender
- Use a **subdomain** only for app mail (for example `mail.example.com`), so its reputation is separate from staff mail.
- `MAIL_FROM_ADDRESS` = `no-reply@mail.example.com` (or `support@…` if replies should reach someone).
- The SMTP provider must allow sending as that address (domain verified in the provider's console).

## 2. DNS records (at the domain's DNS host)

| Type | Name | Value | Notes |
|---|---|---|---|
| TXT | `mail.example.com` | `v=spf1 include:<provider SPF include> -all` | One SPF record per name. Take the `include:` from the SMTP provider. Fewer than 10 DNS lookups in total. |
| TXT (or CNAME) | `<selector>._domainkey.mail.example.com` | `v=DKIM1; k=rsa; p=<public key>` | **2048-bit** key, generated by the provider; many providers give a CNAME instead. |
| TXT | `_dmarc.mail.example.com` | `v=DMARC1; p=none; rua=mailto:dmarc@example.com; adkim=s; aspf=s` | Start with `p=none` (report only). |

## 3. DMARC rollout
1. `p=none` for at least 2 weeks. Read the aggregate reports (`rua`) and check that every legitimate source passes SPF or DKIM aligned.
2. Then `p=quarantine; pct=25`, raise to `pct=100` over a few weeks.
3. Optionally `p=reject` once reports stay clean.

## 4. Check
- `nslookup -type=TXT mail.example.com`, `nslookup -type=TXT _dmarc.mail.example.com`, `nslookup -type=TXT <selector>._domainkey.mail.example.com`.
- Send a password-reset email to a Gmail address and open "Show original": SPF, DKIM and DMARC must all show **PASS**.

## 5. Bounces and complaints
SMTP gives no bounce callback. If the provider can post bounce or complaint events, point it (or a small relay) at
`POST <api>/email/webhook/bounce`, signed as described in `auth-sessions.md` ("Email outbox"). A hard bounce or
complaint stops all further email to that address (`email_suppressions`).
